# ADR 0030: Durable quiet hours for optional personal notices

Accepted 2026-11-09 for the implemented account workspace-setup category (FS-22; NOTIFY-001 Partial).

Add configurable quiet hours to existing account preferences. The feature defaults off, with editable example times 22:00–07:00. Time interpretation is explicitly Asia/Kolkata; start is inclusive, end exclusive, overnight intervals are supported, and equal start/end is rejected rather than interpreted as all-day. All three fields must be supplied together. Legacy PATCH clients omitting them preserve the current quiet policy, and historical command results obtain disabled defaults.

Reuse the durable workspace outbox rather than introduce a parallel queue. The worker first reauthorizes the creator and inserts the deduplicated shared workspace notice. The identity module then evaluates current consent and quiet hours under the existing account preference lock. During quiet hours it returns a durable recheck deadline: the earlier of the quiet interval end or 60 seconds from the database clock. The workspace module sets pending/QUIET_HOURS_DEFERRED, releases its lease, and commits the shared notice. Pending now explicitly means the optional personal portion remains unfinished; it does not hide or delay the shared message.

Each deferral records a completed attempt outcome and audit event but refunds the claim's failure-cycle allowance. Total recorded attempts still include these policy checks; cycleAttempts does not. Real failures retain existing bounded retry/exhaustion semantics. Repeated policy waits cannot exhaust five failure attempts. Restart resumes pending rows, and each execution rechecks authority, opt-in activation time and current quiet policy. Preference changes take effect on the next check within 60 seconds; disabling consent suppresses the optional copy. Existing delivered notices are never recalled. Cancellation preserves any shared notice already delivered.

The existing outbox locking/fencing and recipient/event uniqueness protect against competing workers and repeated completion. V34 adds only validated preference columns, without rewriting applied migrations. OpenAPI 0.31.0 includes quiet fields, grouped-field validation, deferred attempt outcome and pending-status semantics. UI reviews the exact interval/timezone and describes shared/security bypass and recheck latency; operations history displays plain-language deferral guidance.

Bounded polling deliberately trades at most one deferred check/event/minute for reliable preference re-evaluation without a cross-module wake-up write or new infrastructure. Queue/attempt retention and high-volume capacity remain open production concerns. This does not implement other channels/categories or a general scheduling platform.

Evidence: QuietHoursTest verifies same-day/overnight/start/end boundaries; FoundationIntegrationTest checks invalid/equal/incomplete fields, replay and legacy preservation; OperationsIntegrationTest verifies seven deferrals, durable next-attempt state, unconsumed retry budget, immediate shared notice, later unique delivery and fencing. Real desktop/mobile browser journeys verify persisted settings, lost-response retry, pending guidance, worker restart and release after disabling quiet hours. Security notices remain immediate throughout.
