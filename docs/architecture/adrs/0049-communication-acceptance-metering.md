# ADR 0049: Explicit communication contracts and acceptance metering

Accepted 2026-11-10. SAAS-QUOTA-003, FS-05/FS-32.

Bind every workspace communication operation to an immutable contract containing workspace, subscribed plan version, channel, period, allowance and selected metric. Local operator configuration must explicitly supply the allowance and start-inclusive/end-exclusive instants; no production plan allowance or price is inferred. Overlapping periods for one workspace/channel are rejected. New contracts do not rewrite historical measurement.

The implemented metric is **provider_accepted**, supported by local Mailpit and SMS-inbox acknowledgements. One accepted operation consumes one unit. Authorization/dispatch intent is retained as a distinct diagnostic event, not an attempted/delivered/charged measurement. No delivery, reading or provider charge is inferred from acceptance. Delivered, attempted and charged contractual metrics require their own adapters and evidence before selection is supported. WhatsApp and other provider operations remain explicitly unconfigured/unavailable, with null usage rather than fictional zero/unlimited allowances.

The connected workflow is an owner-authorized sandbox metering test to the owner's own linked test contact. It does not enable production messaging features or override the feature entitlement engine. Contact/profile version and immutable contract are confirmed; server-selected content and recipient cannot be replaced by the caller. Sign-in/OTP delivery remains account/platform traffic and is never assigned to an arbitrary workspace. Personal memberships and rental finance are separate.

V50 persists contracts, operations, unique usage events and scoped relationships. Queueing reserves capacity under a workspace advisory lock. Receipt completion uses the same lock so concurrent release/consumption and new reservations cannot overbook the last unit. Operation idempotency is actor/workspace-scoped and binds contract/contact version. Dispatch intent commits before HTTP. The worker reauthorizes ownership, contact version, mode, current subscription and period. Revoked or unavailable work is cancelled before sending. Provider acceptance atomically commits usage and audit; duplicate or late completion cannot consume twice.

A lost HTTP outcome or expired dispatch lease becomes unknown and retains its reservation. It is never automatically resent. A confirmed rejection/cancellation releases the hold; late confirmed acceptance resolves it into exactly one usage event. A database failure after external acceptance is therefore visible/recoverable rather than treated as unsent. This slice does not ship a provider reconciliation UI or production callback adapter: operator-assisted resolution and long-lived unknown outcomes remain an explicit pending recovery dependency, not a claim of completed live-provider recovery.

The private usage page displays channels, metric, period, used/reserved/remaining, confirmations and the latest 25 operation states. It polls with no-store and aborts obsolete context requests. Full historical reporting/pagination belongs to the tracked usage-dashboard scope. Billing restrictions do not block essential authentication or tenancy work through this diagnostic allowance.

Verification uses PostgreSQL last-slot races, replay/changed-body conflict, scoped/revoked access, contract overlap/immutability, duplicate/late receipt evidence and unknown lease handling. Separate real browser tests use the actual local containers, lost response replay and one-message/one-unit assertions. Test receipt injection in integration tests is not live receipt evidence. Production prices, channels, metrics, retention and provider approval remain unconfigured.
